# 从单 Agent 到“讨论—确认—验证”：Windows Codex 多 Agent 第一期开源说明

> 本文是脱敏的技术介绍示例。

复杂任务的难点往往不是“再多生成一段代码”，而是目标是否被正确理解、风险是否被提前发现，以及执行结果是否真正经过验证。

这个第一期原型把协作拆成三个阶段：

1. **并行讨论**：方案角色负责拆解，反方角色专门找风险，调研角色收集证据。
2. **主控确认**：主控只汇总共识、分歧和待确认事项；没有确认不进入执行。
3. **并行验证**：确认后才启动彼此独立的只读检查，并由验证角色报告结果。

## 为什么先限制并发

并发数量越多并不必然更好。相同问题交给多个同质 Agent 往往只会增加重复、成本和上下文噪声。因此第一期把并发限制为两个子 Agent，强调“职责不同、范围独立、证据可复核”。

## 当前验证范围

原型默认在离线模拟模式运行，验证了三件事：讨论角色能够并行汇总；未经确认时流程会停止；确认后两个内置检查会并行完成。完整测试集当前包含 3 项测试。

这不是“已经具备自治开发团队”的结论：真实模型接入、目标项目隔离、合并冲突控制和长期任务恢复都属于后续工作。

## 后续方向

第二期会把执行者放进隔离 worktree，并用范围锁防止互相覆盖；第三期补齐任务板、人工确认、成本控制、失败恢复和真实模型接入。核心原则不变：讨论可以并行，写入必须有唯一负责人，验证必须独立。
