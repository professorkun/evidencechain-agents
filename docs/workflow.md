# 协作流程与验收清单

## 1. 任务入口

- 写清目标、范围、执行端、禁止操作和完成标准。
- 先查已有记录和当前状态，不把历史结论当作当前运行状态。
- 标出需要用户确认的方向变化、写入、重启、外部发送和公开发布。

## 2. 并行讨论

- planner 给出最小步骤和依赖。
- contrarian 检查风险、越界和回滚。
- researcher 收集实际文件、命令输出或官方文档。
- 主控整理共识、分歧、假设与缺失证据。

## 3. 执行与验证

- 确认后才执行；同一写入范围保持单一执行者。
- 先记录基线，再做小范围、可回滚的改动。
- verifier 独立复跑测试和范围检查，不只复述 executor 的报告。
- 交付时说明哪些已修改、已测试、已运行验证，哪些仍待确认。

## 4. 失败处理

失败时保留错误、时间、请求/任务标识和影响范围；先停止扩大操作，再判断是输入、权限、依赖、网络、服务、会话还是代码问题。重试必须说明是否新建会话、是否改变输入，以及如何验证没有重复副作用。
