# Windows Codex Multi-Agent Collaboration

一个面向本机 Codex 的、以审查和证据为中心的多 Agent 协作方案。它把复杂任务拆成不同职责的角色，由主控统一决策，并在任何写入或外部操作前保留人工确认点。

## 这套方案解决什么问题

单个 Agent 往往会同时承担理解、设计、执行和验收，容易出现目标误解、风险遗漏、未经确认的写入，以及“命令成功”被误认为“结果已验证”。本方案把这些责任拆开：

1. 方案角色拆分目标、依赖和验收条件。
2. 反方角色主动寻找风险、越界路径和不可逆操作。
3. 调研角色只收集可复核的代码、文档和运行证据。
4. 主控汇总共识与分歧，决定是否进入下一阶段。
5. 执行角色只在明确范围内实施。
6. 验证角色独立复核改动、测试和完成标准。

## 推荐协作生命周期

`理解 → 并行讨论 → 主控汇总 → 用户确认 → 单写者执行 → 独立验证 → 交付/回滚`

讨论可以并行，但同一文件、配置、数据库或外部系统不得由多个执行者同时写入。删除、覆盖、服务重启、凭据、生产环境和外部发布必须单独确认。

## 角色模板

`agents/` 中的模板可复制到个人 Agent 配置目录。前三个角色默认只读；执行和验证角色仍受父任务的权限、范围和用户确认约束：

| 角色 | 核心职责 | 默认边界 |
| --- | --- | --- |
| planner | 目标拆解、依赖、验收标准 | 只读，不执行 |
| contrarian | 失败路径、风险、错误假设 | 只读，不执行 |
| researcher | 证据收集、来源核对 | 只读，不执行 |
| executor | 实施明确分配的范围 | 单一写入者 |
| verifier | 独立复核范围和结果 | 不替执行者补写 |

## 模型与并发示例

示例使用 `gpt-5.6-luna` 与 `medium` reasoning effort，适合成本敏感且仍需要规划、工具调用和多步判断的任务。模型名称是配置值，不是终端命令。并发上限建议从 2 个子 Agent 开始；资源紧张时回落到 1 个。

```toml
model = "gpt-5.6-luna"
model_reasoning_effort = "medium"

[agents]
enabled = true
max_concurrent_threads_per_session = 2
default_subagent_model = "gpt-5.6-luna"
default_subagent_reasoning_effort = "medium"
```

## 证据与完成层级

每次交付分开报告：文件已修改、测试已通过、已提交/部署、运行中已验证、用户体感已验证、仍需长期观察。不要用旧记录、日期到达、工具返回成功或生成了回复来替代实际验收。

## 不在本仓库内

本仓库不包含任务看板、NAS 部署、OpenClaw 生产配置、私人 Wiki、真实日志、凭据、个人路径或自动发布脚本。它是通用角色和协作规则的公开参考，不代表任何特定环境已经完成生产部署。
