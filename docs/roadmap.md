# 路线图

## 已完成：第一期

- 三个讨论角色并行输出方案、风险与调研意见。
- 主控汇总后通过显式开关决定是否进入执行。
- 两个内置只读验证任务并行运行。
- 默认离线模拟模式与完整单元测试。

## 第二期：安全的并行实现（进行中）

- 为目标项目创建隔离 Git worktree。
- 每项实现从稳定 `main` 建立独立 `codex/` 前缀分支；验证通过后再合并。
- 使用任务合同声明允许范围、基线、依赖和验收标准。
- 建立文件范围锁与单写者规则，阻止多个执行者修改同一资源。
- 由验证角色独立复跑测试并检查改动范围。
- 当前实现：任务合同校验、范围锁、Git worktree 创建、改动范围复核和“仅生成合并建议”的门禁；不执行自动合并。

## 第三期：可观察的长期协作（第一版已完成）

- 持久任务板和运行审计。
- 人工确认界面与暂停/恢复机制。
- 模型调用成本、并发和超时限制。
- 失败恢复、重试策略和真实模型接入。
- 当前实现：本机 SQLite 任务状态与审计记录、状态机、审批门禁、`127.0.0.1` 看板与启动/停止脚本。它不派发 Agent、不执行 SSH、不自动合并；上述适配仍待后续实现与验证。

## 第三期补充：Codex 状态回流（第一阶段已完成）

- 任务记录增加来源、外部 Codex 任务 ID 和同步状态。
- 新增 `POST /api/events`，接收 Codex 侧桥接事件；事件按 `task_id + event_id` 幂等写入。
- 看板增加“已完成 / 异常”历史列，执行输出和外部事件保留在详情审计中。
- 提供 `scripts/post-workbench-event.ps1` 作为本机桥接脚本。
- 第二阶段调整：主线回到工作台自身的任务生命周期。工作台启动脚本不再自动启动 Codex 桥接器；桥接器保留为后续可选的被动观察适配。
- 控制边界：Codex 桥接任务标记为“只读观察”，工作台创建的任务才允许人工确认、进入队列、取消、重试和调用本地执行/验证流程；进入队列的状态接口不能绕过审批记录。
- 当前工作台控制能力：失败/阻塞/中断任务重新提交确认，活动任务取消，所有操作写入审计记录。
- 当前边界：app-server 管理 daemon 的稳定安装和订阅通知尚未验证；桥接器暂不执行、暂停、批准或终止 Codex 任务，也不读取私有 rollout 文件。新建 Codex 会话能否被当前本机 app-server 线程列表稳定发现仍需长期观察；断线重连、事件补偿和真正的实时输出流仍待验证。

## 不在范围内

- 自动绕过用户确认或 Codex 权限。
- 多个 Agent 同时写同一个文件、配置或外部系统。
- 在 NAS 或其他设备部署 Agent、后台常驻自动执行，或让子 Agent 在没有任务合同与用户确认的情况下进行 SSH 写入。经确认后按需分配、受范围约束的子 Agent SSH 任务不属于此限制。
